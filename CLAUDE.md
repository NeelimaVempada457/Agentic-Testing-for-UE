# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a QA automation project for the **Bank of St. Lucia Digital Portal** — combining Playwright E2E testing, Jira requirements traceability, Gherkin BDD scenarios, and AI-powered test generation via Claude Code skills.

**Target application:** `https://bankofstlucia--digitalqa.sandbox.my.site.com`

---

## Common Commands

### Running Tests
```bash
npx playwright test                                      # Run all tests
npx playwright test tests/BDBP1-202/functional          # Run a specific test folder
npx playwright test tests/BDBP1-202/functional/INSTR-FUNC-001.spec.ts  # Run a single test file
npx playwright test --headed                             # Run with browser visible
npx playwright test --ui                                 # Interactive UI mode (debugging)
npx playwright test --grep "test name"                   # Run tests matching a pattern
```

### Reports
```bash
npx playwright show-report                               # Open HTML test report
```

### Jira Integration
```bash
npm run jira:fetch-details                               # Fetch Jira ticket details (uses .env credentials)
```

### Browser Installation
```bash
npx playwright install                                   # Install all browsers
npx playwright install chromium                          # Install Chromium only
```

## Architecture

### Test Configuration
`playwright.config.ts` is the active config. It targets `./tests/`, runs Chromium only, and collects traces/screenshots/videos on failure. `playwright.config.js` is a legacy file with multi-browser defaults — do not use it for new test runs.

- **Timeouts:** 30s per test, 10s per action, 30s navigation
- **Retries:** 2 on CI, 0 locally
- **Parallelism:** Fully parallel locally; 1 worker on CI
- **Output:** HTML report + `test-results/results.json`

### Directory Structure

| Directory | Purpose |
|---|---|
| `tests/` | Playwright test suite. Functional tests live under `tests/<JIRA-ID>/functional/` |
| `tests/BDBP1-202/functional/` | 8 spec files (INSTR-FUNC-001 through INSTR-FUNC-008) for the registration form instruction section |
| `features/` | Gherkin `.feature` files, coverage JSON, risk analysis, and regression scenarios — generated by `/generate-test-cases` |
| `reports/` | Coverage analysis and Requirements Traceability Matrix (RTM) |
| `jira-output/` | Cached Jira ticket data fetched by `npm run jira:fetch-details` |
| `src/lib/jira/` | Jira API client (`client.js`) and config loader (`config.js`) using axios |
| `test-results/` | JSON and HTML Playwright execution results |
| `test-artifacts/` | AI-generated test case analysis and logs |

### Test File Conventions
- Spec files are named `INSTR-FUNC-NNN.spec.ts` and map to individual acceptance criteria.
- Shared navigation and setup helpers are in `tests/BDBP1-202/functional/helpers.ts`.
- `tests/seed.spec.ts` handles page initialization state.

### Jira Integration
Credentials are loaded from `.env`:
```
JIRA_BASE_URL=https://unitededucators.atlassian.net
JIRA_EMAIL=...
JIRA_API_TOKEN=...
```
The `src/lib/jira/client.js` module wraps axios with base auth headers. Fetched data is cached under `jira-output/<TICKET-ID>/`.

### Claude Code Skills
Custom skills in `.claude/skills/` power the AI-assisted workflow:
- `/generate-test-cases` — Crawls a live app and generates test cases + Gherkin + coverage reports
- `/generate-gherkin` — Converts Jira ticket acceptance criteria into `.feature` files
- `/fetch-jira-details` — Fetches and caches Jira ticket context for downstream agents
- `/early-defect-consolidator` — Consolidates Discrepancies.md findings into a single validated Jira bug after human approval

The MCP server (`playwright run-test-mcp-server`, configured in `.mcp.json`) enables the Playwright-Test-Planner, Playwright-Test-Generator, and Playwright-Test-Healer agents used by these skills.

**MANDATORY RULE — playwright-test-generator source of truth:**
When generating Playwright `.spec.ts` test scripts, the `playwright-test-generator` agent MUST read test cases from `test-artifacts/<TICKET-ID>/test-cases/` (Markdown files with steps, test data, and expected results). Never use `features/` Gherkin `.feature` files as the input source for script generation. The `features/` directory is a BDD artifact only — it is not the input to the generator. The seed file for page setup is `tests/seed.spec.ts`.

**MANDATORY RULE — Skills and Commands must always be created together:**
Every skill file created under `.claude/skills/<name>.md` MUST have an identical copy at `.claude/commands/<name>.md`. Claude Code reads `.claude/commands/` to register slash commands; without the command file the `/name` slash command will not appear. Whenever creating or updating a skill, always create or update the matching command file in the same operation. Never create a skill without its command file.
